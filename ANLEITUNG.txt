============================================================
  EMAIL-PROCESSOR – EINRICHTUNGSANLEITUNG (Outlook)
============================================================

VORAUSSETZUNGEN
---------------
- Microsoft Outlook ist installiert und eingeloggt (Microsoft 365)
- Ollama ist installiert und läuft (llama3.2 Modell geladen)
- Python ist installiert (https://www.python.org/downloads/)
  → Bei Installation "Add Python to PATH" anhaken!


SCHRITT 1: Hotels und E-Mail-Adressen eintragen (config.yaml)
--------------------------------------------------------------
Öffne config.yaml (z.B. mit Notepad) und trage ein:

a) Für jedes Hotel:
   - name: Exakter Hotelname
   - email: E-Mail-Adresse des Hotels
   - keywords: Begriffe, die im E-Mail-Text auf dieses Hotel hinweisen

   Beispiel:
     - name: "Stadthotel München"
       email: "info@stadthotel-muenchen.de"
       keywords: ["stadthotel münchen", "münchen", "stadthotel"]

b) Bewerbungs-Weiterleitungsadresse:
   applications_email: "hr@deine-firma.de"


SCHRITT 2: Installation
------------------------
Doppelklick auf: install.bat
→ Installiert alle benötigten Python-Pakete


SCHRITT 3: Programm starten
-----------------------------
1. Ollama starten (läuft dann im Hintergrund)
2. Outlook öffnen und eingeloggt lassen
3. Doppelklick auf: start.bat
→ Das Programm läuft im Hintergrund und prüft alle 5 Minuten
  neue E-Mails im Posteingang


SCHRITT 4: Autostart einrichten
---------------------------------
Damit das Programm automatisch mit Windows startet:

1. Windows-Taste → "Aufgabenplanung" öffnen
2. Rechts: "Einfache Aufgabe erstellen..."
3. Name: "Email Processor"
4. Trigger: "Beim Anmelden"
5. Aktion: "Programm starten"
6. Programm/Skript:
   C:\Users\Werkstudentfibu\email_processor\start.bat
7. Fertigstellen

Hinweis: Outlook und Ollama müssen beim PC-Start automatisch starten.
→ Win+R → shell:startup → Verknüpfungen von Outlook und Ollama hineinkopieren


OUTLOOK-ORDNER (werden automatisch erstellt)
---------------------------------------------
Das Programm erstellt folgende Unterordner im Posteingang:

  EmailProcessor/
  ├── Abgemeldet          ← Newsletter erfolgreich abgemeldet
  ├── Newsletter-Manuell  ← Abmeldung manuell nötig
  ├── Bewerbung           ← Weitergeleitet an HR
  ├── Werbung             ← Ignorierte Werbemails
  ├── Buchung/
  │   ├── Hotel Name 1    ← Weitergeleitet an jeweiliges Hotel
  │   └── Hotel Name 2
  ├── Buchung-Unbekannt   ← Hotel nicht erkannt, manuell prüfen
  ├── Sicherheitswarnung  ← Verdacht auf Phishing/Schadsoftware, NICHT öffnen, im Dashboard prüfen
  ├── Unbekannt           ← Nicht klassifizierbar
  └── Fehler              ← Verarbeitungsfehler


PHISHING-/SCHADSOFTWARE-FILTER
--------------------------------
Jede eingehende E-Mail wird vor der normalen Klassifizierung automatisch auf
verdächtige Merkmale geprüft:
  - Gefährliche Anhangstypen (.exe, .scr, .vbs, .js, .lnk, ...) und
    makrofähige Office-Dokumente (.docm, .xlsm, ...)
  - Verschleierte doppelte Dateiendungen (z.B. "rechnung.pdf.exe")
  - Links, deren sichtbarer Text eine andere Domain nennt als das
    tatsächliche Ziel, sowie Links auf reine IP-Adressen
  - Typische Phishing-Formulierungen ("Konto gesperrt", "Passwort bestätigen", ...)
  - Absendernamen, die eine bekannte Marke nennen, aber von einer
    abweichenden Domain kommen

Treffer werden NIEMALS automatisch gelöscht oder weitergeleitet. Die E-Mail
wird lediglich sofort in EmailProcessor/Sicherheitswarnung verschoben und
rot markiert. Im Dashboard erscheint sie mit den erkannten Gründen zur
manuellen Prüfung — erst nach deiner Genehmigung wird sie endgültig archiviert.
Zusätzlich bewertet auch Ollama jede E-Mail auf Phishing/Betrugsversuche
(z.B. CEO-Fraud ohne Anhang/Link) und behandelt Treffer genauso.

Zusätzlich werden folgende Reputationsquellen abgefragt:
  - Windows Defender: scannt jeden Anhang lokal (kein Internet-Zugriff,
    kein Setup nötig, läuft automatisch mit)
  - URLhaus (abuse.ch): kostenloser Abgleich von Links gegen eine Liste
    bekannter Schadsoftware-/Phishing-URLs (kein API-Key nötig)
  - VirusTotal: prüft Anhänge (Datei-Hash) und Links gegen 70+ Antiviren-
    Engines — nur aktiv, wenn im Dashboard unter Konfiguration → Sicherheit
    ein kostenloser API-Key (registrieren auf virustotal.com) eingetragen wurde
Diese externen Prüfungen laufen nur bei E-Mails von außerhalb (nicht bei
internen Kollegenemails), damit keine internen Daten an Drittanbieter
gehen und das kostenlose API-Kontingent geschont wird.

WICHTIG — was der Filter NICHT abfangen kann:
Bei der bekannten "Ich bin kein Roboter"-Betrugsmasche (z.B. gefälschte
Booking.com-Beschwerde-Mail) führt der Link zu einer externen Webseite mit
gefälschter Verifizierung, die auffordert, "Win+R" oder ein Terminal zu
öffnen und einen kopierten Befehl einzufügen — dadurch installiert sich die
Schadsoftware selbst. Dieser Schritt passiert außerhalb der E-Mail (auf der
fremden Webseite) und kann von keinem E-Mail-Filter technisch verhindert
werden. Die Erkennungsmaßnahmen oben (insb. URLhaus/VirusTotal-Link-Check
und die Booking.com/Marken-Erkennung) sollen die auslösende E-Mail schon vor
dem Klick abfangen. Als zusätzlicher Schutz gilt für alle im Team:
  → NIEMALS Text von einer Webseite in "Ausführen" (Win+R), PowerShell
    oder die Eingabeaufforderung einfügen — das verlangt kein echtes
    CAPTCHA oder keine echte Verifizierung, das ist immer Schadsoftware.

HÄUFIGE PROBLEME
-----------------
"Ollama connection error" / Verbindung zu Ollama fehlgeschlagen
  → Ollama starten: Windows-Taste → "Ollama" suchen → öffnen
  → Oder im Terminal: ollama serve

"Modell nicht gefunden"
  → Im Terminal prüfen: ollama list
  → In config.yaml den Modellnamen anpassen (ollama_model)

"Outlook nicht gefunden"
  → Outlook öffnen, dann start.bat erneut starten

"Hotel nicht erkannt" → E-Mail landet in Buchung-Unbekannt
  → In config.yaml mehr keywords für das Hotel eintragen
  → E-Mail manuell an das Hotel weiterleiten

"Abmeldung nicht möglich" → E-Mail landet in Newsletter-Manuell
  → Newsletter manuell im Postfach abbestellen
